# AI爬塔 1.0.16 Lua：联机状态分岔排查与修正

## 实机报告与判断边界

用户两人使用 1.0.15，职业为巨魔投手和兽人战士，未经过小游戏。在精英战斗中看不见对方攻击、攻击似乎未生效，但防御/结束回合仍可见，两边敌人血量不同，未见红色 Lua 报错。

这是游戏状态分岔的强烈迹象，不能只改行动点显示。当前没有取得双方运行日志、同步校验或可重复的 KK 双机现场，尚不能宣称找到该局唯一根因，也不能宣称实机已经修好。

## 已确认的代码风险及改动

1. `core/runtime.lua` 原先在启动时设置 `runtime.handle_level=2`。本地引擎文档明确规定：完整 userdata 持有原生对象引用，Lua 回收对象时释放引用。YDWE 引擎实现中，`jhandle_ud_push` 调用 `handle_ref`，`jhandle_ud_gc` 调用 `handle_unref`。这使原生对象编号的回收时机可能受各客户端 Lua GC 影响。本地选中对象、打开不同面板和查看提示会产生不同的 Lua 引用与分配，不能拿这种回收时机决定共享战斗对象的生命周期。
2. 在任何生成模块运行前改为 `handle_level=1`：使用 lightuserdata，不由 Lua GC 增减 Warcraft 原生对象引用；保留原生 null 对应 Lua nil 的行为，没有改成会把空对象变成数字 0 的 level 0。正常对象的创建、停止和删除继续由同步规则执行。禁止运行中切换模式。代价是 Lua 不再保护已删除对象的旧引用；不能在 Destroy/Remove 后继续使用旧对象。
3. `game/minigames.lua` 的生成器停止流程原本用 `pairs` 遍历以计时器对象为键的表。改成保存创建顺序并按数值索引清理，跳过已结束生成器。用户本局未经过小游戏，因此这不是对本次故障的归因，而是同时消除另一处原生对象删除顺序不稳定的风险。
4. 增加 `game/sync_diagnostics.lua`。任意一人在聊天中输入 **`-sync`**，双方处理同一聊天事件，各自输出当前层/回合、战斗状态签名、脚本随机调用次数、施法事件数、伤害事件数，以及英雄/敌人的对象编号、血量、行动点、毒层与输出数据。签名还包括位置、魔法、护甲、属性和倍率。它只读状态，不重新投骰、不创建临时单位或计时器、不扣资源、不写存档、不强行用一方血量覆盖另一方。

引擎依据：[YDWE 原生句柄封装实现](https://github.com/actboy168/YDWE/blob/master/Development/Plugin/Warcraft3/yd_lua_engine/lua_engine/class_handle.cpp)，以及源码包 `tools/vendor/jass2lua/lua-engine.md` 的 `runtime.handle_level` 文档。此依据支持上述生命周期风险，不等于复现用户这局故障。

## 战斗链核查

- 巨魔投矛保留原来的数值跳动、最终随机比例、延迟生成 `e00R` 投射物、命中与毒矛被动。没有把原伤害改为界面本地计算。
- 兽人重砍保留数值跳动、最终比例、位移、延迟伤害和返回位置。
- 两种攻击共享原伤害处理中的暴击、最终倍率、输出统计；防御直接修改护甲，结束回合通过原事件和计时器推进。
- 本次没有改职业公式、毒层公式、随机范围、战利品、云存档键、原生技能/背包控件或 HUD 位置。

## 验证结果与覆盖边界

共 **90 组模型检查**通过：17 行为、8 操作、31 界面、4 关卡生命周期、16 随机房、6 小游戏、8 新增双端战斗检查。结果保存在 `audit/lua-*.txt` 和相关 JSON。

新双端检查创建两个独立 Lua 游戏状态，用同样的同步输入、不同的本地玩家/选中对象/提示查看次数/GC 次数执行实际生成的规则函数：

- 巨魔与兽人同时在随机数跳动过程中攻击，逐段比较双方血量、AP、随机流和结算记录；实际执行投射物创建/下令、近战延迟回调、毒矛被动和伤害总计。
- 连续防御正确扣 AP 并增加相同护甲。
- 原结束回合计时器等待双方结束后只进入一次敌方回合。
- 原毒伤结算造成正伤害并减少一层毒。
- 原新回合回调恢复 AP、清除临时护甲、解除暂停。
- 联机诊断不改变战斗；人为改变一端的血量或 AP，签名能检出差异。
- 小游戏模型补充检查结束清理按创建顺序处理尚未结束的生成器。

**测试模型不是 Warcraft 引擎。** 巨魔原生投射物的实际碰撞/攻击行为用延迟命中模型提供，未做图形、网络包、真实原生句柄回收、KK 双机或云存档验收。双端模型的一致性不能证明上述 GC 风险就是该局根因，也不能证明不存在其他失步入口。

44 个 Lua 模块及打包入口语法通过；打包启动模型通过；PJASS 通过；81 项资源检查通过；109 个原地图块与 75 个具名成员的 StormLib 读回通过。旧 1.0.15 地图和源码包哈希保持不变。

## KK 验证方法

两人使用 **1.0.16** 新开一局；旧的失步对局不会因为换文件自动恢复。优先复测原组合在小怪、精英中的交错攻击、毒伤和下一回合 AP。任意一人输入 `-sync` 后，比较双方**同一编号**诊断的签名；不需要两人同时输入。若不同，保留双方输出与出现异常的动作。相同签名只代表本次采样字段一致，不是整个 Warcraft 世界的完整校验。
